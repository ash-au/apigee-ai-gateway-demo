Interactive Technical Reference & Plain-English Guide

System 1 (TypeSafe Jev), Decomposed Noul Battery & AI Routing Glossary

Core Idea: Traditional LLMs output words (e.g., "Yes" or "No"), which forces your API gateway to make brittle all-or-nothing guesses. TypeSafe Jev is a non-generative System 1 model that outputs calibrated probabilities (`0.00` to `1.00`) across three structured primitives: Noul, Choice, and Score.
Term / Primitive Plain-English Explanation How We Use It in Apigee X (Tab 5)
Noul
Soft Boolean / Calibrated Probability in $[0, 1]$ 		Instead of returning a hard true or false, a Noul returns a continuous, calibrated probability between 0.00 (definitely false) and 1.00 (definitely true).

You can optionally pass criteria: {"true": "...", "false": "..."} to explicitly anchor what counts as a positive vs. negative condition. 		In Stage 1, requires_formal_proof returns 0.99 on the Raft/FLP theorem query and 0.01 on the KMS key rotation lookup.

In Stage 2, each defect check returns a Noul probability (e.g., missed_user_constraint: 0.99).
Noul Battery
Decomposed Multi-Head Verification 		Why single questions fail: If you ask a model one broad holistic question—"Is this response bad enough to escalate?"—it averages out everything that looks polite and well-formatted, returning a deceptively low score (~0.04–0.15) even when one specific number was hallucinated or one bullet was skipped.

The Battery Solution: Just like a hospital runs a battery of specific blood panels instead of asking "Is the patient sick?", a Noul Battery decomposes verification into 5 specific, independent failure-mode heads evaluated in a single pass. 		Our Stage 2 verifier runs 5 Noul heads simultaneously:
1. hallucinated_or_contradicts_context
2. missed_user_constraint
3. superficial_or_unproven
4. internal_contradiction
5. hedging_or_refusal
Plus __overall__::holistic_escalate_judge for comparison.
any_flag Gate
max(noul_battery) > fire_threshold 		Because the Noul Battery asks 5 specific defect questions where True = Defect, we do not average them. Instead, we take the maximum across all 5 heads:
any_flag = max(head_1, ..., head_5) > 0.70.
If even one head exceeds fire_threshold ( marked <== FIRES), Apigee X rejects the cheap $L_1$ Flash response and escalates to System 2 (`gemini-2.5-pro`). 		In Scenario 3, when $L_1$ Flash fabricates a region and skips a bullet, `missed_user_constraint` spikes to 0.99 <== FIRES and `hallucinated_or_contradicts_context` hits 0.89 <== FIRES, immediately triggering $L_2$ Pro recovery.
Choice
Mutually Exclusive Classification + Confidence 		Picks one option from a mutually exclusive set of categories and returns:
1. choice: The winning label.
2. probabilities: Calibrated probability for every option (summing to 1.00).
3. confidence: How certain Jev is (`0.00` to `1.00`), enabling confidence-gated routing. 		In Stage 1, target_tier classifies the query into:
• flash_fast
• flash_with_verifier
• pro_system2_direct
Gated by confidence ≥ 0.75.
Score
Continuous Expected Value over Ordered Rubric 		When an LLM is asked to rate complexity on an integer scale of 0, 1, or 2, borderline prompts jitter randomly between 1 and 2.

Jev's Score computes the probability of each rubric level ($P(0), P(1), P(2)$) and returns the smooth Expected Value:
$E[\text{Score}] = 0\cdot P(0) + 1\cdot P(1) + 2\cdot P(2) \in [0.0, 2.0]$. 		Stage 1 measures query complexity ($0.00$ to $2.00$) to tune Gemini's `thinkingBudget`.
Stage 2 measures response_quality ($0.00$ to $2.00$) of the $L_1$ Flash completion.
Concept What It Means Why It Matters for AI Gateway FinOps
System 1 Model
(jev-latest) 		Inspired by Daniel Kahneman's Thinking, Fast and Slow. System 1 is fast, instinctive, single-pass judgment. It does not write essays or generate chain-of-thought text; it reads the state once and outputs calibrated probabilities (`Choice`, `Score`, `Noul`) in ~190–220ms. Costs $0.042 per 1M input tokens and $0.00 for output tokens (~30x cheaper on input than Gemini 2.5 Pro and free on output). Ideal for high-speed API gateway routing and verification gates.
System 2 Model
(gemini-2.5-pro) 		System 2 is slow, deliberative, step-by-step reasoning. It generates internal thinking tokens (`thoughtsTokenCount`) and detailed autoregressive text completions to solve hard proofs or complex edge cases. Costs $1.25 / 1M input and $10.00 / 1M output + thinking tokens. Calling System 2 on every simple lookup wastes 80–90% of enterprise AI budgets.
Direct System 2 Fast-Track
(pro_system2_direct) 		In standard FrugalGPT cascades, every query is sent to $L_1$ Flash first. But if a query asks for a formal distributed consensus proof, $L_1$ Flash is guaranteed to fail—so calling $L_1$ first just wastes 1.5 seconds and $L_1$ tokens before escalating anyway. When Stage 1 Jev detects choice == "pro_system2_direct" (with confidence ≥ 0.75) or requires_formal_proof ≥ 0.82, Apigee X's Route-VertexPro routes straight to Gemini 2.5 Pro, skipping the doomed $L_1$ call.
SDE Cascade
(Staged Deferral & Escalation) 		For the ~85% of enterprise traffic that is simple or moderate, Stage 1 routes to $L_1$ (gemini-2.5-flash). Stage 2 then audits the $L_1$ answer with the 5-head Noul Battery. Only if a defect head fires (> 0.70) does the gateway escalate to $L_2$ (gemini-2.5-pro). Delivers 85%–89% net cost reduction on routine traffic while preserving frontier Gemini 2.5 Pro accuracy whenever $L_1$ Flash hallucinates or misses a constraint.
Technical Term Plain-English Explanation (Zero Jargon) Concrete Analogy / Gateway Impact
Autoregressive Text Generation How generative LLMs (like Gemini or GPT) write answers: they predict one word (token) at a time in a sequential loop. To generate 300 words, the model must run its giant neural network 300 separate times, feeding each new word back into the input. Analogy: Typing a letter one character at a time on a typewriter. Because of this sequential loop, generative LLMs are slow (1–6 seconds) and charge high fees for every output/thinking token.
Single-Pass Forward Inference How System 1 models (like Jev or DeBERTa) work: the model reads the entire input prompt + context all at once in a single parallel matrix operation and immediately outputs the classification/probability numbers—no word-by-word generation loop. Analogy: Stamping a document in one motion instead of typing a paragraph. Takes ~190ms and has $0.00 output token cost.
Logits The raw, unscaled score numbers that come out of the final layer of a neural network before they are converted into percentages (for example, raw scores like [-1.8, +0.4, +4.2]). Logits can be any negative or positive number (`-100` to `+100`), so they cannot be used directly as a `0.70` gateway threshold until converted via Softmax.
Softmax A mathematical formula ($e^{z_i} / \sum e^{z_j}$) that squashes raw logits into clean positive probabilities between 0.00 and 1.00 that add up to exactly 1.00 (100%). Turns raw logits into the probability breakdown you see in Tab 5: e.g., {"flash_fast": 0.97, "flash_with_verifier": 0.03, "pro_system2_direct": 0.00}.
Calibrated Softmax & ECE (Expected Calibration Error) Standard LLMs are notoriously overconfident: their raw Softmax might output 0.99 certainty even when they are wrong 40% of the time (high Calibration Error).

A Calibrated model has its probabilities aligned with real-world accuracy: when Jev outputs a Noul of 0.80, that event is empirically true ~80% of the time. 		Why it matters: Without calibration, setting a gateway slider like fire_threshold = 0.70 is meaningless because raw LLM scores cluster at 0.00 or 1.00. Calibration makes numeric sliders work reliably.
Selective Prediction
("Abstention / Deferral") 		A model's ability to measure its own uncertainty (`confidence`) and say "I am not sure enough to make this call—defer to a safer verification path." If Jev's Stage 1 Choice confidence (`0.62`) is below your Confidence Gate (0.75), the gateway refuses to trust a blind fast route and enforces mandatory Stage 2 `Noul` verification.
Bidirectional Cross-Encoder vs. Causal Decoder Causal Decoder (Generative LLMs): Reads strictly left-to-right to predict the next word.
Cross-Encoder / System 1 Evaluator: Reads the User Query, RAG Context, and Candidate Response together, allowing every word in the response to cross-check every word in the RAG context simultaneously. 		Makes System 1 models exceptionally fast and accurate at spotting factual contradictions (`hallucinated_or_contradicts_context`) and omitted constraints (`missed_user_constraint`).
